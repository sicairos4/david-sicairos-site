Both allowed routes remain inside the same WebView. No credentials, callback allowlists or signing identities are changed.

The former native welcome, duplicate account-entry choices and About/version dialog are removed from the launch flow. Help remains available through the existing workspace help and workspace-start.html routes. The root Back action asks whether to leave rather than return to another welcome screen. Safe system/keyboard insets remain; this does not hide Android system controls or add offline saving.

Google sign-in retains the existing external authorization and package callback/PKCE/session-handoff implementation. The provider screen is deliberately not forced into the WebView. Successful return is intended to load the workspace inside the app. Operator callback configuration and the installed artifact remain separate dependencies. External destinations still require the existing browser confirmation.
