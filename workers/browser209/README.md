# Core browser worker source
Prepared 2026-11-08. No tests, browser requests, dependency installation or database writes were executed to prepare this commit. This is executable source, not a running service or a completed Facebook repair. It persists the core implementation previously confined to the chat package; it does not upload all 27 package files.

Use ops/browser-hosting/install-host.sh with this directory as its source. Requires an owner-controlled Debian/Ubuntu Linux host for that installer, Python 3.11+, PostgreSQL connectivity, and a visible desktop for first login. Browser hosting/cloud authentication is still unresolved. Dependency ranges are not a tested lockfile. No Airtop dependency.

Copy accounts.example.json privately to accounts.json, configure an exact authorized account, and leave other accounts disabled. BROWSER_ACCOUNTS_FILE selects that private file. BROWSER_STATE_DIR selects a private persistent directory. Run `python browser_worker.py login ACCOUNT_KEY` on the actual host; sign in yourself and close using Enter. The browser209 host service and first-login process must use the same OS identity and state directory. Session creation is not proof of access validity. Account selectors and provider resource domains are placeholders/examples, not live-verified adapters. Login challenges require owner interaction, not bypass.

Schema installation is separate and is not performed by this commit. schema.sql creates a private browser_209 staging queue with RLS enabled and no ordinary-runtime access policy or grants. An authorized migration must configure separate operator and worker permissions before use. Do not provide a service-role or database-owner credential to a recurring browser worker. The CLI propose/approve commands are operator actions; they are not a production self-approval mechanism. BROWSER_DATABASE_URL must refer to the appropriate scoped connection for the current process and enforce TLS certificate verification. Production worker permissions must not allow creating or approving its own tasks.

A payload is exactly an object with a steps array. Supported steps: {action:goto,url:HTTPS_URL}, {action:observe,selector:UNIQUE_LOCATOR,expected_text:EXACT_TEXT}, {action:fill,selector:UNIQUE_LOCATOR,text:EXACT_TEXT}, {action:click,selector:UNIQUE_LOCATOR}. Use real JSON with quoted strings. No arbitrary shell, JavaScript or page-supplied natural-language instructions are executed. A click can publish or cause another external action; only approve the exact permitted target and steps. Identity must match before every fill/click. A navigation-only job is still an external request, not an offline test. No jobs are created by this source commit.

Operator CLI: `python browser_worker.py propose ACCOUNT_KEY PAYLOAD_FILE UNIQUE_IDEMPOTENCY_KEY --due ISO_UTC_TIME --expires LATER_ISO_UTC_TIME`; then `python browser_worker.py approve RETURNED_UUID`. Approval displays the exact proposal and requires typing its digest. Host consumer: `python browser_worker.py run-once`. The worker claims one approved, unexpired due job transactionally. Errors leave an uncertain record or, if persistence fails/crashes, possibly running; never blindly replay either. Successful step execution is executed_unverified, not a platform acceptance receipt or public visibility proof.

Pending production work: linkage to ai_coordination authorizations; independently scoped role policies; cross-host account leases; revocation during execution; platform receipts/reconciliation; caps, quiet hours, and duplicate-route prevention. Host-local locks do not coordinate multiple hosts. Do not enable recurring browser publication until these pieces exist. The existing Muse v2 endpoint accepts only health.snapshot and queue.summary, not these browser steps. No existing cron schedule is changed here.

Use an outbound network firewall blocking internal/metadata destinations. Per-request DNS/public-IP checks are defense in depth, not complete DNS-rebinding protection. Keep Chromium sandboxing enabled. No cookies, profiles, credentials, env files, or private payloads belong in GitHub or shared Drive. Encrypted profile backup/restore and automatic failover are not implemented in this commit.
